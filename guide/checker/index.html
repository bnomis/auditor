    The audit checker¶

    auditor check .

    The checker is the mechanical half of the auditme skill: a static sweep, written against the standard library only, that parses each file and prints one JSON object per hit. It reports; it never decides. Triage is the reviewer's job, and acceptance is the accept marker's.

    It needs Python 3.14 or later. The ruff and ruff-version-drift rules run the ruff named by the AUDITME_RUFF environment variable when it is set, else the project's .venv/bin/ruff when that is executable, else ruff from PATH, and lockfile-drift runs uv lock --check. Set AUDITME_RUFF to the path of a ruff outside the project's .venv, for example one a CI job installs elsewhere:

    AUDITME_RUFF=/opt/tools/ruff-0.17.4/bin/ruff auditor check .

    A value that is not an executable file stops the sweep with exit 2.

    What it audits¶

    Every path is relative to the project root passed as the first argument.

    • Packages under src/<package>/: each package is audited in its own pass, so module names are built without a src. prefix. src/ is optional.
    • Declared roots: when [tool.auditme] in pyproject.toml declares roots, those are the swept roots, in place of the packages and extra roots below.
    • Scripts in bin/: the default extra root, used when it exists and holds .py files. --extra-root replaces the default set.
    • A .py file directly in src/: it belongs to no pass, so it is reported as a src-loose-module hit.
    • Markdown: every .md file under the root is read for spec-api-signature-drift, except those in a hidden directory or in a .git, .venv, node_modules, __pycache__, audit-reviews or tasks directory.
    • Project files: pyproject.toml with uv.lock and .pre-commit-config.yaml are read by the project-level checks (see Project-level checks); AGENTS.md is read only by per-root checks (the gated rules and the import rules).

    No other directory is swept.

    Running it¶

    auditor check: the full report¶

    auditor check <project-root> [--package <pkg>] [--extra-root <dir> ...]
    Flag Effect
    --package <pkg> Audit only src/<pkg>/. Drops the extra roots and the src-loose-module report too. For re-checking one package while verifying a fix; a normal audit passes neither flag.
    --extra-root <dir> Audit <dir> (relative to the root) as its own pass. Repeatable. Replaces the default set (bin/). A named root that does not exist is an error, not an empty pass.

    auditor check prints every hit, accepted or not, and exits 0 whatever it finds. It exits 2 on a usage error from argparse (an unknown option or a missing value); when the root is not a directory; when --package is not a plain directory name; when a named extra root is outside the root or is not a directory; when the --package directory is missing or is a file; or when [tool.auditme] in pyproject.toml is invalid. A project with no package and no extra root prints a note on stderr and exits 0.

    auditor changed: the gate¶

    auditor changed           # changed files only
auditor changed --all     # every file

    auditor changed [--all] [--base <ref>] [<repo-root>] runs auditor check over the whole tree, so cross-file rules see every file, then keeps the unaccepted hits in scope. It exits 1 when any remain, or on any failure: an argument error, a --base that is a flag, git that cannot run, a diff or rev-parse that fails, a repository root that cannot be resolved, or a sweep that cannot start, times out, exits non-zero, prints a line that is not a JSON object, or reports a crashed check. It exits 0 otherwise. A sweep that cannot run is never skipped.

    Mode Scope Runs as
    default Files changed in <base>...HEAD, plus tracked files changed in the index or working tree against HEAD (an untracked file is in scope once staged). A hit is in scope when its path, or any of its related paths, is. The auditme-changed pre-commit hook
    --all Every file The auditme-all hook: the push gate and CI

    --base defaults to the first of @{upstream}, origin/main and main that resolves. A value starting with - is refused, whichever spelling of the option gave it, so it is never read by git as an option. With none, or with no reportable file changed (a .py file, a uv.lock, or a .md file outside hidden directories and outside audit-reviews and tasks, among others), it prints why and exits 0 without sweeping. <repo-root> defaults to the working directory's git top level.

    To see which lines changed rather than which hits remain, --scope runs no sweep and prints one JSON line per changed .py or .sh file:

    auditor changed --scope --base <commit>

    Each line is {"path": ..., "ranges": [[start, end], ...]}. A Python range is a diff hunk widened to its enclosing function, else its enclosing class; a shell range is the hunk. The audit skill gives these ranges to its sampled reviewers between whole-tree audits, so a small edit does not reopen a whole file.

    The same runs through pre-commit:

    pre-commit run auditme-all --hook-stage manual --all-files

    To let one commit or push through, SKIP=auditme-changed git commit or SKIP=auditme-all git push.

    Reading the output¶

    auditor check prints one JSON object per line, keys sorted:

    {"accepted": false, "accepted_reason": null, "evidence": "except Exception:", "line": 9, "path": "src/pkg/core.py", "rule": "silent-broad-except", "variant": "no logger and no raise in body"}
{"accepted": true, "accepted_reason": "best-effort read of an optional cache", "evidence": "except Exception:", "line": 17, "path": "src/pkg/core.py", "rule": "silent-broad-except", "variant": "no logger and no raise in body"}
{"accepted": false, "accepted_reason": null, "evidence": "def load(path, strict): | src/pkg/core.py:6", "line": 6, "path": "docs/spec.md", "related": ["src/pkg/core.py"], "rule": "spec-api-signature-drift", "variant": "load: spec says (path, strict), source says (path)"}
    Key Meaning
    rule The rule id (see The rules)
    variant Which form of the rule fired, or a summary of this hit
    path Repository-relative path, or null for a hit with no file
    line 1-based line, or null
    evidence The source snippet or identifier that matched
    accepted true when an accept marker or, for in-function-import only, an AGENTS.md row covers the hit; an AGENTS.md row for layering-violation makes the check print no hit at all
    accepted_reason null for a hit that is not accepted; otherwise the marker's reason, no reason given for a marker with none, or AGENTS.md accepted (<importer> -> <imported>) for an in-function-import hit an AGENTS.md row covers
    related Only on a hit that compares files: the other files' paths, sorted, never the hit's own

    Identical hits are printed once, so a hit that several passes would each report appears once.

    auditor changed prints only unaccepted hits in scope, sorted by path and line, as <path>:<line> <rule> with the variant indented beneath, then how to fix or skip:

    src/pkg/core.py:9  silent-broad-except
    no logger and no raise in body

Fix each hit, or accept one with a comment on its line or the line above:
    # auditme: accept[<rule>] <reason>
To skip this check for one commit: SKIP=auditme-changed git commit

    Accepting a hit¶

    Fix the hit, or accept it with a comment on the hit's line or the line above:

    def other(path):
    try:
        return open(path).read()
    # auditme: accept[silent-broad-except] best-effort read of an optional cache
    except Exception:
        return None

    The marker matches # auditme: accept[<rule>] <reason> anywhere on the line, so it can follow code or a # noqa. A few rules (from-import, except-interpolation, spec-api-signature-drift) also take a marker on any line of a statement that spans several lines.

    • Scope it to a rule. accept[<rule>] answers only for that rule; a hit from another rule on the same line stays unaccepted. The unscoped form, # auditme: accept <reason>, answers for every rule on the line, including rules added after it was written, so write new markers scoped.
    • One marker per rule. A line that two rules hit can carry two scoped markers, # auditme: accept[rule-a] <reason> # auditme: accept[rule-b] <reason>; each reason ends where the next marker begins.
    • Give a reason. It is copied into accepted_reason and is what a reviewer reads instead of re-arguing the hit.
    • Line-1 markers. src-loose-module is reported at line 1, so its marker goes on line 1 of the file: # auditme: accept[src-loose-module] <reason>.
    • File-level rules. empty-init-while-siblings-export is accepted by a marker on any line of the __init__.py. phase-section-doc-reference skips a whole file that carries a comment-only line matching # auditme: accept ... phase-section ... (unscoped, with phase-section in the reason).

    • Markdown. A spec-api-signature-drift hit is accepted by the same comment inside the fenced block, on the def line, the line above it, or any line of the signature:

      ```python
# auditme: accept[spec-api-signature-drift] strict lands in the next change
def other(path, strict):
    ...
```

    • AGENTS.md tables. An in-function-import hit is accepted by a table row in the project's AGENTS.md pairing the importer and imported module in backticks, written without a src. prefix (pkg.config.structures). A layering-violation is accepted by a pair in the accepted-exceptions table of the AGENTS.md Package Layering section.

    Hits a marker cannot accept

    ruff hits come from ruff and are silenced the ruff way (# noqa: <code> or the project's ruff config). lockfile-drift, auditme-check-crash and unreadable-file have no marker either: regenerate the lockfile, fix the checker, or make the file readable. A project can add rules to this list with never-accepted, below.

    Never-accepted rules¶

    A project that fixes every hit of a rule, and wants no marker to excuse one, lists the rule in pyproject.toml:

    [tool.auditme]
never-accepted = ["silent-broad-except", "layering-*"]

    Each entry is a rule name, or a family: a name ending in * matches every rule that starts with the text before it (layering-*). The * may appear only at the end. A marker for a listed rule no longer accepts the hit: the hit is reported with accepted false, and the marker's reason is copied into refused_reason, so the reviewer sees what was refused. The hit has to be fixed. An entry that matches no rule exits 2, so a misspelt name cannot leave every marker for that rule counting. never-accepted can sit beside roots in the same table.

    Nothing else counts as acceptance: not a prior review, a decision note, or a belief that the pattern is intentional.

    The rules¶

    Each rule's predicate, and every carve-out that keeps it from firing, is in the docstring of its check_* function under src/auditor/rules/; the hits auditor check emits itself (see Driver below) have no such docstring. Rules marked gated fire only when the project's AGENTS.md declares the standard they enforce.

    Which shared rule each checker rule enforces is listed under "Rules enforced by a check" in the agents repository's rules reference (https://bnomis.github.io/agents/reference/rules/).

    Driver¶

    Emitted by auditor check itself, not by a registered check.

    Rule id Reports
    src-loose-module A .py file directly in src/, outside any package
    unreadable-file A file a check could not read (gone, denied or not UTF-8); path names it and evidence is always cannot read <name>, without the reason. The check skips it and reports its other hits.
    auditme-check-crash A check raised; variant names it and evidence the exception. auditor changed fails on it.

    Project-level checks¶

    A project-level check asks about the project, not a package, and runs once (PROJECT_CHECKS in registry.py), whatever the number of passes:

    • ruff-version-drift reads .pre-commit-config.yaml and is anchored at the ruff-pre-commit rev: line, where its marker goes. It is silent with no config or no ruff-pre-commit repo; a rev that names no version, and a ruff that cannot run, are hits.
    • lockfile-drift runs only when both pyproject.toml and uv.lock exist, and reports a uv that cannot run as a hit.
    • spec-api-signature-drift reads every Markdown file in scope against the whole corpus, so a per-root pass would repeat it. It fires only when the name resolves to exactly one module-level definition.

    Every other check runs once per pass, over that pass's root. Among them, layering-violation, as-import and in-function-import read AGENTS.md for their gate or their acceptance tables, and ruff runs over the pass's root. The driver prints identical hits once.

    The pinned version and upgrades¶

    Projects pin the auditme-changed and auditme-all hooks to a revision of this repository, so a new rule never fails a build until the project chooses to upgrade. Upgrading can surface hits in code that passed before; fix or accept them in the same commit as the upgrade. The commands are in Upgrading the checker, and installing and adopting the hooks is covered in Setting up the shared guards.
