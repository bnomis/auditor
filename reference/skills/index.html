    Skills¶

    Each skill is a directory under claude/skills/<name>/ holding a SKILL.md and any scripts or templates it uses. bin/install-claude.sh links claude/skills/ into ~/.claude/skills/, so each skill is available in every project as ~/.claude/skills/<name>/. The other shared skills are in the agents repository (bnomis/agents, https://bnomis.github.io/agents/).

    Invoke a skill in Claude Code as /<name> [args], or by asking for what it does: the when_to_use list in each skill's frontmatter names the phrases that trigger it ("audit the code", "set up a new project").

    Skill Invocation Purpose
    auditme /auditme [scope] Scripted and checklist audit of code, specs and docs
    auditme-project-setup /auditme-project-setup new [path], /auditme-project-setup adopt [path] Install the shared audit hooks, CI gate and project files

    /auditme¶

    /auditme [scope] [--category <category>]

    Scope is empty (specs, src/, bin/, docs/, AGENTS.md, README.md), a file path, a spec slug, or the docs. --category (standards, architecture, performance, security, testing, dependencies, documentation) is a debugging aid; a normal audit runs every category.

    • Runs: the scripted sweep auditor check <project-root>, then a fixed checklist (a listed question runs one reviewer per batch of its candidates; a sampled question runs on the lines changed since the previous review, each widened to its enclosing function, and on the whole tree every third audit and on any audit with no previous **Commit:**), then a spec review and re-verification of earlier findings.
    • Refuses to start while auditor rules pending reports open change requests in the rules repository's TODO.md.
    • Writes: agents/audit-reviews/review-N.md, agents/audit-reviews/summary.md, agents/audit-reviews/index.md, the Phase B ledger (agents/audit-reviews/ledger/<question>.jsonl), and marks shipped tasks done in agents/tasks/audit-reviews/.
    • Then: runs /taskdev agents/audit-reviews/review-N.md if there are findings.
    • Stops for: uncommitted changes; commit (docs(audit): add review-N).

    The checker, its rules and accept markers are described in The checker.

    /auditme-project-setup¶

    /auditme-project-setup new [<path>]
/auditme-project-setup adopt [<path>]

    Path defaults to the current repository root. Templates are in claude/skills/auditme-project-setup/templates/.

    • new: writes .pre-commit-config.yaml (ruff, shellcheck, and the auditme-changed and auditme-all hooks pinned to this repository's current main commit), .github/workflows/ci.yml, AGENTS.md, CLAUDE.md, TODO.md, DONE.md and claude/rules/README.md; installs the pre-commit and pre-push hooks. Asks before overwriting an existing .pre-commit-config.yaml, .github/workflows/ci.yml, AGENTS.md, TODO.md or DONE.md.
    • adopt: adds the auditme hooks, offers to remove a project-local hook doing the same job, and counts unaccepted hits with pre-commit run auditme-all --hook-stage manual --all-files. At zero hits it enables the pre-push stage and adds the CI audit step; otherwise it files a dated TODO.md item instead and enables neither gate.
    • Stops for: the project name and test command; a failing git ls-remote of the auditor repository (no network access); overwriting an existing project file (new); removing a project-local hook (adopt); commit. Never pushes. CI needs no key or secret: the hooks clone the public auditor repository over HTTPS.
