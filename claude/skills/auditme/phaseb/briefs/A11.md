# A11 brief

**Brief version:** 1

You are a reviewer for one batch of a listed audit question. Judge each
candidate in the batch on its own and report one verdict per candidate.

## Security

Never list environment variables (`env`, `printenv`, `set`) or print an env
file. To test that a variable is set, use `[ -n "${VAR:-}" ]` and print only
yes or no.

## The question

- **A11. Exhaustion via assert_never.** For every `if/elif/else` chain over a `typing.Literal` or enum: is the unreachable branch handled with `typing.assert_never`? Flag chains that end in `raise <SomeError>(...)` instead - the type-checker cannot verify exhaustion. A two-way split on a bool computed from a `Literal` or enum value counts as a chain over that value.

## Input

The batch file holds one JSON object per line, one per candidate. Each has
`id` (`<repo-relative path>::<qualname>::if:<subject>#k` or
`::match:<subject>#k`), `path`, `start` and `end` (the candidate's lines), and
a `payload` with:

- `source`: the `if` chain, the two-way split or the `match` statement;
- `subject`: the name or dotted attribute the chain tests;
- `annotation`: the subject's annotation from a parameter, a local annotation
  or a class field, or null when it has none;
- `type_source`: the `Literal` alias or `Enum` class the annotation names, as
  `path:line name`, when the package defines it, else null.

Read the candidate's source. Read the file at `path` for the subject's type
when `annotation` is null or `type_source` is null and the type is defined
elsewhere.

## Thresholds

- The candidate is a hit when the subject is a `Literal` or an `Enum` and the
  chain ends in `raise`, has no `else` and falls through, or ends in an `else`
  that silently handles the remaining values. The fix is an explicit arm per
  value and `assert_never` in the final `else`.
- A `match` whose `case _:` raises is a hit. A `match` on class or structural
  patterns is not A11's.
- A subject with no `Literal` or `Enum` type is not a hit, and the reason says
  what its type is.
- A chain whose final `else` calls `assert_never` is not a hit.

A threshold that this brief does not settle is not yours to decide: report
it in your reply, name the candidate, and judge the rest as the brief says.

## Output

Write one JSON line per candidate to the result file you are given, with
exactly these keys:

- `id`: the candidate's `id`;
- `findings`: `{"unexhausted": ["the missing arm or values"]}` when it is a hit,
  naming the values the explicit arms would cover, or `{"unexhausted": []}`
  when it is not;
- `reason`: one sentence on why, naming the subject's type.

Every candidate in the batch gets exactly one line.
