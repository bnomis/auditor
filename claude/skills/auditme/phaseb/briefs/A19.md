# A19 brief

**Brief version:** 2

You are a reviewer for one batch of a listed audit question. Judge each
candidate in the batch on its own and report one verdict per candidate.

## Security

Never list environment variables (`env`, `printenv`, `set`) or print an env
file. To test that a variable is set, use `[ -n "${VAR:-}" ]` and print only
yes or no.

## The question

- **A19. Wrong logger level for broad-except.** For every `except Exception` / `except BaseException`: does the body use `logger.exception` (not `warning`/`error`/`info`/`debug`)? And conversely, is `logger.exception` reserved for unexpected failures, not expected graceful-degradation paths? A broad handler that degrades gracefully fails one half of this question whichever level it uses; the fix is to remove or narrow it - see [Conflicts with no winner](#conflicts-with-no-winner).

## Input

The batch file holds one JSON object per line, one per candidate. Each has
`id` (`<repo-relative path>::<qualname>::except#k`), `path`, `start` and `end`
(the handler's lines), and a `payload` with:

- `handler`: the `except` clause and its body;
- `try`: the whole `try` statement;
- `function`: `name`, `signature`, `returns` (the return annotation or null)
  and `last_statement` of the enclosing function, or null at module level;
- `log_calls`: each logger call in the handler as `level: text`.

Read the candidate's source. Read the file at `path` when the handler's
surroundings decide the verdict.

## Thresholds

- A handler that raises passes the first half if it logs only at `exception`
  or not at all.
- A handler that does not raise and carries on (returns any value,
  `continue`, `pass`, or falls through to a default) is graceful degradation.
- A broad graceful-degradation handler is a hit at any level. The fix is
  "remove or narrow" from `SKILL.md`'s conflicts with no winner.
- A narrow handler that calls `logger.exception` and degrades gracefully is a
  hit: `logger.exception` is reserved for unexpected failures.
- A function returning `int` is a command exit path, not degradation.

A case this brief does not settle is not a finding: judge it not flagged,
name the candidate and the case in your reply, and judge the rest as the brief
says. Every reviewer gives an unsettled case the same verdict, so it does not
depend on the batch; the operator settles a reported case when it should count.

## Output

Write one JSON line per candidate to the result file you are given, with
exactly these keys:

- `id`: the candidate's `id`;
- `findings`: `{"handler": ["what is wrong and the fix"]}` when it is a hit,
  or `{"handler": []}` when it is not;
- `reason`: one sentence on why, naming whether the handler raises or
  degrades.

Every candidate in the batch gets exactly one line.
