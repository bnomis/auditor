# T2 brief

**Brief version:** 2

You are a reviewer for one batch of a listed audit question. Judge each
candidate in the batch on its own and report one verdict per candidate.

## Security

Never list environment variables (`env`, `printenv`, `set`) or print an env
file. To test that a variable is set, use `[ -n "${VAR:-}" ]` and print only
yes or no.

## The question

**T2. Property-based tests.** Domains that are well-defined (data shapes, config combinations) have hypothesis tests.

## Input

The batch file holds one JSON object per line, one per candidate. Each has
`id` (`<repo-relative path>::<qualname>`), `path`, `start` and `end` (the
candidate's lines), and a `payload` with:

- `params`: each annotated parameter as `{name, annotation}`;
- `returns`: the return annotation's text;
- `types`: the package classes the annotations name, each as `{id, path,
  start, end}`;
- `pairs`: the ids of candidates whose names are inverses of this one
  (`parse` and `format`, `encode` and `decode`, `to` and `from`, `dumps` and
  `loads`);
- `tests`: each test the index found reaching it, as `{id, path, start, end,
  route, via, property}`; `property` is true for a test decorated with
  hypothesis `given`;
- `test_files`: the test files that import the candidate's module or a
  caller's module.

Read the candidate's source, each listed type and each listed test. Read
`test_files` for calls the map could not follow.

## Thresholds

- The candidate is covered when a test with `property: true` calls it
  directly.
- Flag a candidate only when the `reason` states a property its domain
  supports: a round trip with a `pairs` entry, idempotence, an output
  invariant, a simpler oracle or a bound.
- With no property statable, do not flag it, and say why in the `reason`.
- Whether the project declares hypothesis does not change the verdict.
- A test in a file that imports neither the candidate's module nor a
  caller's module does not re-plan a candidate; `--rejudge` covers it.
- A call through a name assigned from the candidate itself (`check =
  module.fn`, then `check(x)`) in a `given` test is a direct call of the
  candidate: it is the same object.

A case this brief does not settle is not a finding: judge it not flagged,
name the candidate and the case in your reply, and judge the rest as the brief
says. Every reviewer gives an unsettled case the same verdict, so it does not
depend on the batch; the operator settles a reported case when it should count.

## Output

Write one JSON line per candidate to the result file you are given, with
exactly these keys:

- `id`: the candidate's `id`;
- `findings`: `{"missing": ["property test"]}` when it is flagged, or
  `{"missing": []}` when it is covered or no property is statable;
- `reason`: one sentence on why, stating the property when flagged.

Every candidate in the batch gets exactly one line.
