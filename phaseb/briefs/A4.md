# A4 brief

**Brief version:** 2

You are a reviewer for one batch of a listed audit question. Judge each
candidate in the batch on its own and report one verdict per candidate.

## Security

Never list environment variables (`env`, `printenv`, `set`) or print an env
file. To test that a variable is set, use `[ -n "${VAR:-}" ]` and print only
yes or no.

## The question

**A4. Docstring `Raises` accuracy.** For every function whose docstring has a `Raises:` section: does the body actually raise each declared exception type, and only those? Flag mismatches. A declared type is raised if the body raises it, or calls a function in the same package that raises it and does not catch it; an undeclared domain error that reaches the caller that way is a mismatch. The sweep's `raises-section-drift` rule checks the mechanical part: it follows each same-package callee, including `<ClassName>.<method>(...)` for a class the package defines, through its declared `Raises:`, and follows a callee with no section into its own raises and callees, up to three calls deep; it nets out handlers that catch without re-raising, and reports each omitted name, and each declared name that a handler in the function catches and nothing else raises. It skips a callee error guarded only by optional arguments the call leaves unset (`if strict: raise ...` called without `strict`). Phase B reviews the other value-dependent cases (fixed names, pre-checked values, dispatch types) and what the sweep cannot resolve: calls on instances, `cls.<method>()` calls, inherited methods, callables passed in, errors stored and raised later, and declared names reaching only through those.

## Input

The batch file holds one JSON object per line, one per candidate. Each has
`id` (`<repo-relative path>::<qualname>`), `path`, `start` and `end` (the
candidate's lines), and a `payload` with:

- `raises`: the text of the candidate's `Raises:` section;
- `callees`: the package functions its calls resolve to, followed
  transitively, each as `{id, path, start, end}`;
- `unresolved`: each call the resolver could not follow, as `path:line` and
  its source text.

Read the candidate's source, every listed callee and every unresolved call.
Trace an unresolved call by hand to find what it reaches.

## Thresholds

- A domain error is a class the audited package defines. Never count a
  builtin or a third-party class, whether declared or raised.
- Each class counts separately. Declaring a base class does not cover a
  subclass that reaches the caller, and declaring a subclass does not cover
  its base.
- An error reachable only through a callable passed in as an argument is not
  owed in the `Raises:` section.
- An error that the candidate can reach only through a constant it passes
  itself, where that constant rules the error out, is not owed. Name the
  constant in the `reason`.
- A handler that catches an error without re-raising removes it from what
  reaches the caller.

A threshold that this brief does not settle is not yours to decide: report
it in your reply, name the candidate, and judge the rest as the brief says.

## Output

Write one JSON line per candidate to the result file you are given, with
exactly these keys:

- `id`: the candidate's `id`;
- `missing`: domain error class names the candidate lets reach its caller
  that its `Raises:` section does not declare, sorted;
- `extra`: domain error class names its `Raises:` section declares that
  nothing in the candidate or its callees raises to the caller, sorted;
- `reason`: one sentence on why, naming the constant where a threshold
  above rules an error out.

Every candidate in the batch gets exactly one line, including those with
empty `missing` and `extra`. A candidate with no mismatch has both lists
empty.
